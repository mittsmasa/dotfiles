# /slide - スライドデッキ生成

モノトーンデザインのスライドデッキを Slidev で作り、`slidev export` で PDF にする。デザイン(CSS・レイアウト・Key Message コンポーネント)は [assets/slidev-template/](assets/slidev-template/) に固定してあり、本文は `slides.md` に Markdown で書く。

## 入力

`$ARGUMENTS`: テーマ名、構成指示、または原稿テキスト。

## ワークフロー

1. **構成設計** — スライド構成案を提示、ユーザー承認を得る(骨子 `slide.md` があればそれに従う)
2. **デッキ作成** — テンプレートを `slides/` にコピーして `pnpm install`。手順と環境のクセは [references/slidev.md](references/slidev.md)
3. **本文執筆** — `slides/slides.md` を下記デザインシステムに沿って書く。テンプレート同梱の `slides.md` はコンポーネントのショーケースなので、読んでから上書きする
4. **export** — `pnpm pdf`(→ `deck.pdf`)と `pnpm png`(→ `png/*.png`)。sandbox 外で実行する
5. **目視検証** — `png/*.png` を開いて確認。問題あれば `slides.md` を直して再 export

骨子 `slide.md`(slide-outline skill が作る)と Slidev の本文 `slides.md` は別ファイル。取り違えない。

## レイアウト原則

コンポーネント単体のデザインが正しくても、配置がページごとにブレると資料全体が素人くさくなる。以下を全スライドで守る。

- **骨子(slide.md)の表現形式指定に従う**。骨子の「載せる」に箇条書き / 表 / 対比リスト / 図などの形式が書かれていればその通りに作る。指定が無いスライドは、形式を提案して骨子側に書き戻してから slides.md に書く(slides.md 側で表現を発明しない)
- **タイトルスライドを1枚目に置く**。骨子側にタイトルが無ければ「後で決める(仮)」のまま作る
- **Key Message はライトボックス(`<KeyMessage>`)で紙面の最下部・全幅に統一**。上に置いたり左に寄せたりしない。聞き手の視線の置き場を固定するため
- **ボックスの使い分けに論理を通す**。ボックスは Key Message 専用にする。本文・例示・補足は箇条書きで書く(プレーンテキスト)。「なんとなく囲む」とボックスの意味が失われ、読み手がどれが結論か判別できなくなる
- **黒背景は図の要素(プロセスのノード、エージェント等)専用**。紙面の文を黒背景ボックスで強調すると図と見た目が被り、図なのか文なのか区別がつかなくなる
- **同じ図をページ間で再掲するときは、同じ位置・同じサイズ・同じ要素の並び順で出す**。図の再登場は「あの話がこう変わる」の対比装置なので、位置や順序がズレると対比が壊れる。積み増し系(吹き出しが増える等)は、要素が無いページでも同じグリッドを敷いて位置を固定する(Key Message が無いページには `<KeyMessage spacer />` を置いて同じ高さを確保する)
- **文字は大きく、言葉は少なく**。本文の目安は 17px 以上。文が長くて入らないなら、縮小せずキーワード化する。話す内容は骨子(slide.md)のノート欄にあり、紙面に全部載せない(slides.md の発表者ノート `<!-- -->` に移す)
- **余白の間延びに注意**。中央や中段にぽっかり空白ができるレイアウトは、要素の justify を見直す。情報量が薄すぎるページは骨子側に戻して統合を提案する
- **要素を端に置き去りにしない**。左上に小さな要素がひとつ、のような配置は視線が迷子になる
- **SVG図は `.fig` コンテナに収まる高さを事前に計算する**。`.fig` は `flex:1` で残り領域を使うが、SVG の `width`/`height` 属性がそのまま描画サイズになる。見出し・本文・Key Message の高さを差し引いた残り領域より図が大きいと、Key Message が紙面下にはみ出す。図が大きい場合は `viewBox` は変えずに `width`/`height` 属性だけ縮小して収める
- **同じ概念を表す図の要素は、ページを跨いでも同じ形にする**。「AIエージェント」のような繰り返し登場する概念を、あるページでは角丸バー、別のページでは丸ノードのように描き分けない。形が変わると同一の存在だと認識されず、対応関係が伝わらない
- **矢印は指す先の具体的な要素まで正確に届かせる**。箱の中の特定のラベル(知識チップ等)を指したいなら、箱全体の縁ではなくラベルの位置まで伸ばす。ただし他の要素(役割名など)を突っ切らないよう、途中に浮いた矢印にならないか確認する。座標は勘で置かず、[slidev.md](references/slidev.md) の実測手順で終点の実座標を取ってから当てはめる

## デザインシステム

### 基本仕様

- サイズ: 1280x720(16:9)。headmatter の `canvasWidth: 1280` で固定
- フォント: Noto Sans JP(headmatter の `fonts` で Google Fonts から読み込む)
- カラー: #1A1A1A / #555 / #999 / #F9F9F9 / #FFF
- 実装: [style.css](assets/slidev-template/style.css)、見本: [slides.md](assets/slidev-template/slides.md)

### 共通構造

- window-bar(黒 40px + 赤黄緑のドット)はレイアウトが描く。slides.md には書かない
- 1 枚目は `layout: cover`(h1 + h3 を中央配置)。2 枚目以降は default レイアウト
- 本文領域は padding 40px 60px 18px。要素は縦に並び、`<KeyMessage>` は `margin-top: auto` で最下部に寄る

### コンテンツ領域

window-bar(40px)+ padding 上下(58px)を除いた実効コンテンツ領域は **約 622px**。
h2 + h3 で約 120px 使うため、見出し付きスライドの本文領域は **約 500px**。
詰め込みすぎに注意。

### タイポグラフィ

| 要素 | 書き方 | サイズ | ウェイト | 色 | 装飾 |
|---|---|---|---|---|---|
| タイトル | `# ` (cover) | 54px | 700 | #1A1A1A | — |
| 見出し | `## ` | 38px | 700 | #1A1A1A | 下線 4px |
| サブタイトル | `### ` | 20px | 400 | #555 | 左バー 4px。任意 |
| 本文(箇条書き) | `- ` | 28px | 400 | #333 | 黒丸。サブ項目(インデント)は 22px。2カラム内は 24px。入らないなら縮小せずテキストを短くする |
| 強調 | `**太字**` | — | 700 | #1A1A1A | — |
| Key Message | `<KeyMessage>` | 32px | 700 | #1A1A1A | グレーボックス、最下部・全幅・中央寄せ |
| テーブル | Markdown の表 | 21px | 400 | #333 | ヘッダのみ黒背景 |

### コンポーネント

| 用途 | 書き方 | 使い方の決まり |
|---|---|---|
| Key Message | `<KeyMessage>文</KeyMessage>` | 1 スライド 1 個まで。Key Message 専用のライトボックス(#F9F9F9 + 細ボーダー)。補足・例示はボックスにせず箇条書きで書く |
| Key Message の場所取り | `<KeyMessage spacer />` | Key Message が無いページで、図の位置を他ページと揃えるための透明スペーサー |
| 図の領域 | `<div class="fig">` | 見出しと Key Message の間の残り領域を使い、中身を中央に置く |
| 横並び | `<div class="fig-row">` | 図の要素を横に並べる(gap 16px) |
| 図のノード | `<div class="stage">` / 矢印 `<span class="arr">→</span>` | 黒背景。プロセスのノード、循環図の箱、エージェント等。紙面の文の強調には使わない |
| 吹き出し | `<p class="bubble">` / 残像 `class="bubble dim"` | 台詞用。白地 + しっぽ + 影。グレー版は「前のスライドの残像」。Key Message と見た目を分けるため必ずしっぽ付き |
| 区画 | `<div class="room"><p class="name">名前</p>…</div>` | 破線の白枠。範囲・領域を表す。区画同士の独立は間隔(gap)だけで示し、あいだに壁要素を足さない |
| チップ | `<p class="chip">` | 区画内の概念ラベル。黒 = 図のノード扱い。文言はページ間で統一 |
| ツールアイコン | `<span class="tool"><span class="tile">Cf</span>Confluence</span>` | 実サービスを図に添えるとき。ロゴ画像は使わず頭文字タイル + 名前(取得・ライセンスの手間があり、モノトーン紙面で色が浮くため) |
| 目次(中扉) | `<ol class="agenda">` + `li.done` / `li.now` / 無印 | 全章を最初から見せる。済み = グレー + ✓、現在地 = 太字、未来 = 薄グレー |
| 対比の箇条書き | `- **問題** → 向き合い方` | 通常の箇条書き。難所や Q&A 系に |
| 2 カラム | `<div class="cols"><div>…</div><div>…</div></div>` | 48% ずつ。中で Markdown を書くときは前後に空行 |
| プレースホルダー | `<div class="placeholder">` | 未確定の画像・図の配置場所 |

区画・吹き出し・Key Message は 3 つとも別の見た目にしてある。グレー背景を共有すると役割が判別できなくなるため、新しい部品を足すときもこの区別を崩さない。

### レイアウトパターン

1. **タイトル** — cover レイアウト。h1 + h3 中央配置
2. **見出し + 本文** — h2 + h3 + 箇条書き + Key Message
3. **見出し + 2カラム** — `.cols` で比較・テキスト+図
4. **見出し + テーブル** — データ比較
5. **見出し + 図** — `.fig` の中に図の要素。Key Message が無ければ spacer
6. **目次(中扉)** — h2 + `.agenda`

### CSS の自由度

Slidev は Vue + UnoCSS 上で動くので、HTML/CSS のフル機能が使える(疑似要素、SVG、インライン style)。ただし色・サイズ・部品の見た目は `style.css` のクラスを使い、slides.md 側で新しい見た目を発明しない。足りない部品はテンプレートの `style.css` に足してからショーケースにも載せる。
